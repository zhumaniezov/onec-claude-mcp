# Из чего складывается подключение Claude Code к 1С

Для каждой базы администратор задаёт адрес веб-публикации и учётную запись. Claude Code запускает локальный MCP-процесс, который обращается к двум HTTP-интерфейсам базы. Стандартный OData обслуживает чтение и запись. Сервис расширения даёт дополнительное описание конфигурации в контексте пользователя. Такая схема позволяет сменить конфигурацию и СУБД, сохранив коннектор. Названия доступных коллекций и полей он получает из конкретной публикации. [Стандартный REST-интерфейс 1С](https://1c-dn.com/1c_enterprise/rest_interface/)

## Claude Code и MCP

Локальный stdio-сервер регистрируется командой `claude mcp add [options] <name> -- <command> [args...]`. В версии 2.0 для Windows команда указывает на EXE из релиза. При установке из wheel запускается интерпретатор виртуального окружения с аргументами `-m onec_mcp --config <путь>`. Команда `/mcp` показывает состояние соединения Claude Code с процессом. Для проверки доступности конкретной базы предназначен инструмент `onec_status`. [Подключение MCP к Claude Code](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server) · [Официальный Python SDK MCP](https://github.com/modelcontextprotocol/python-sdk)

В stdio каждая строка стандартного вывода содержит протокольное сообщение. Для диагностики предназначен stderr. Инструменты объявляют схему аргументов и назначение операции. Короткие описания и небольшие результаты помогают модели выбрать инструмент и не расходовать контекст на полную выгрузку базы. [Транспорт MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) · [Инструменты MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) · [Рекомендации Anthropic для авторов инструментов](https://www.anthropic.com/engineering/writing-tools-for-agents)

## Что требуется от базы

1. Включить стандартный интерфейс OData в веб-публикации и настроить в базе состав доступных объектов. Это две разные настройки. В прикладных решениях с подходящей версией БСП может быть доступна обработка «Настройка автоматического REST-сервиса». Схема по адресу `…/odata/standard.odata/$metadata` показывает результат настройки. [Настройка и примеры запросов 1С](https://1cfresh.com/articles/data_odata) · [Публикация стандартного REST API](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Integration/Publishing_standard_REST_API_for_your_infobase/)
2. Для HTTP-методов расширения подключить CFE в базе, разрешить вызов сервиса в веб-публикации и выдать интеграционному пользователю роль сервиса. Для выборочной публикации HTTP-сервиса расширения руководство 8.3.27 предусматривает запись `service` в существующем разделе `httpServices` файла `default.vrd`. Общий параметр `publishExtensionsByDefault` действует сразу на сервисы всех подключённых расширений. В облачной базе возможность установки и публикации CFE зависит от порядка, установленного провайдером. [Руководство администратора 1С, раздел 3.21.4](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/)
3. Для чтения и записи прикладных объектов пользователю нужны соответствующие права в базе. Платформа использует для OData аутентификацию веб-сервисов, проверяет права и вызывает обработчики событий. 1С отдельно оговаривает исключение для проверок заполнения. Обязательные реквизиты, значения по умолчанию и результат записи следует проверить на примере конкретной конфигурации. [Поведение платформы при чтении и записи](https://1c-dn.com/1c_enterprise/rest_interface/)

## Смысл операций с данными

- `POST` создаёт объект. `PATCH` изменяет переданные реквизиты. Пример фирмы 1С использует адрес записи со ссылочным ключом `guid'…'`. Для изменения или удаления ранее прочитанной записи платформа документирует заголовок `If-Match` со значением полученной версии `DataVersion`. [Примеры HTTP-запросов 1С](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Integration/Publishing_standard_REST_API_for_your_infobase/) · [Руководство разработчика, Optimistic data blocking](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf)
- Запись `DeletionMark=true` меняет пометку объекта. Платформа различает изменение реквизита и вызов метода `УстановитьПометкуУдаления()`. Метод может дополнительно отменять проведение документа или помечать подчинённые элементы. При изменении только реквизита рассчитывать на эти эффекты нельзя. Стандартная процедура «Удаление помеченных объектов» отдельно проверяет ссылки. [Стандарт 1С об использовании пометки удаления](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/Applied_objects/) · [Руководство администратора 1С](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/)
- `DELETE` удаляет запись. В примере 1С:Фреш сервер возвращает HTTP 204 с пустым телом, после чего запись исчезает из справочника. Прямое удаление может оставить ссылки на отсутствующий объект. [Пример удаления записи, раздел 6.3.6](https://1cfresh.com/articles/data_odata) · [Прямое удаление в 1С](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/Applied_objects/)

## Проверка на отдельной информационной базе

На файловой 1С **8.3.27.1644** с Apache **2.4.71** создание элемента справочника вернуло HTTP 201. Чтение и изменение реквизита вернули 200. После записи `DeletionMark=true` объект открывался и содержал установленную пометку. Физическое удаление вернуло 204, повторное чтение того же GUID — 404. В отдельной базе читатель с ролью расширения получил описание своего справочника. Документ, на который ему не дали право чтения, отсутствовал в ответе. Пользователь без роли сервиса получил 403.

В той же базе стандартный `$metadata` вернул читателю схему публикации, включая имя закрытого документа и имя скрытого реквизита. Запрос на чтение коллекции этого документа получил HTTP 401. Поэтому наличие коллекции в EDMX означает, что она опубликована. Возможность читать её записи определяется учётной записью.

Сервис расширения 1.1.0 вернул для доступного справочника максимальные длины в 9 символов для кода, 25 для наименования и 60 для пользовательского реквизита «Примечание». Закрытый для просмотра строковый реквизит длиной 17 символов в ответ не попал. Для недоступного документа и отсутствующего справочника сервис одинаково ответил HTTP 404. Другой пользователь с правом на документ получил максимальную длину его номера — 11 символов.

На этом же стенде обнаружилось существенное расхождение с документацией 1С. После успешной записи изменилось значение `DataVersion`. Повторный прямой запрос `PATCH` с предыдущей версией в `If-Match` получил **200**, и последующее чтение подтвердило перезапись. Поэтому контроль версии средствами одного HTTP-заголовка на этой публикации не даёт гарантии от одновременной записи.

Универсальность здесь означает подключение разных совместимых веб-публикаций. Для файловой базы тоже требуется публикация. Адрес файла `1Cv8.1CD`, строка `Srvr=…;Ref=…` и адрес СУБД обозначают другие способы доступа. Отправной точкой для выбора операций служат опубликованная схема, класс объекта и права интеграционного пользователя. Составные ключи регистров, проведение документов и бизнес-процессы имеют собственные контракты. Полный интерфейс 1С шире набора инструментов коннектора. [Объекты и специальные операции OData в 1С](https://1c-dn.com/1c_enterprise/rest_interface/)
