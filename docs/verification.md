# Проверка Python-коннектора 2.1.0

## Профили, предпросмотр и журнал

Проверка 20 ноября 2026 года в Windows x64. Автотесты используют отдельные временные файлы SQLite и локальные HTTP-фикстуры. Приёмочный стенд использует Apache на loopback и отдельную файловую базу 1С 8.3.27.1644 с синтетическими справочником, документом, табличной частью и разными пользователями.

| Что проверено | Результат |
| --- | --- |
| Состав ответа | Реальный EDMX содержит отдельный набор для строк табличной части. В ограниченных профилях списки, описания и чтение показывают только разрешённые поля. Отдельный набор строк требует собственного допуска. Даже при возврате всей записи сервером проверена фильтрация на выходе MCP. |
| Предпросмотр и выдача билета | Автотесты проверили значения до и после, изменённые позиции и колонки, удаление строк и очистку части. При частичном доступе к колонкам полная замена существующей части блокируется. |
| Журнал SQLite | Проверены запись намерения до отправки, отказ при недоступном журнале, успешное применение, конфликт, отказ, потеря связи, отмена запроса и ошибка финализации. Проверена выдача UTF-8 JSON через --audit-show, в том числе при системной кодировке CP1251. |

## Приёмка собранных дистрибутивов

Через установленный wheel и через готовый EXE независимый клиент MCP повторил каждый сценарий на отдельных синтетических объектах. Подключение использовало stdio, а запросы — опубликованный HTTP-сервис и стандартный OData 1С. Оба процесса завершились по EOF с кодом 0.

| Сценарий | Результат |
| --- | --- |
| Область записи | Пустой список закрыл атомарные изменения. Пользователь с правами записи данных получил отказ при настройке списка. Администратор назначил одну коллекцию. Пока документ оставался за пределами списка, редактор не смог изменить его даже с прикладными правами на этот документ. Отзыв списка прошёл. |
| Видимость данных | Ограниченный профиль получил заданные реквизиты и один разрешённый столбец табличной части. Закрытое значение не попало в ответ изменения и журнал. Обращение к нему через select или фильтр отклонено. |
| Изменение строки | Справочник создан через OData с двумя строками. Предпросмотр показал замену значения и удаление второй строки. После применения контрольное чтение подтвердило состав и значение оставшейся строки. |
| Конкуренция | Два одновременных независимых запроса к расширению передали одну DataVersion. Ответы — 200 и 412. Изменение, внесённое отдельно через стандартный OData, также сохранилось при обращении к расширению со старой версией. |
| Справочник и документ | Обе поставки выполнили создание, изменение, пометку и физическое удаление для каждого типа. Контрольные чтения подтвердили правки и вернули 404 после удаления. Применение устаревшего плана и повтор билета отклонены. |
| Журнал после записи | Независимое чтение SQLite и команда --audit-show подтвердили GUID, логин 1С, идентификатор операции и исход. |

Автоматически прошли 38 тестов исходной версии. Пять из них также запущены через готовый EXE, включая цикл CRUD через stdio и проверку журнала. Подробности проверки прежнего механизма OData сохранены в [протоколе 2.0.0](https://github.com/zhumaniezov/onec-claude-mcp/blob/v2.0.0/docs/verification.md).

Claude Code подтвердил **Connected** для EXE и установленного wheel в отдельном локальном профиле. У расширения **OneCMCP.cfe 1.2.0** SHA-256 **351b679d944828cc1d14dfd082e74d421d11a102782186dc361e1f2ef98e75c2**. Официальный BSL Language Server сообщил 0 ошибок, 18 предупреждений и 100 информационных замечаний. Исходники проверены по выгрузке собранного CFE.

Этот же CFE загружен в отдельную базу 8.3.18.1208. Конфигуратор применил расширение и проверил серверные модули и внешнее соединение, все три команды завершились с кодом 0. Полный цикл CRUD и параллельные сеансы проверены на 8.3.27.1644.

Сценарии с правами и конкурентным доступом необходимо повторить на копии конкретной конфигурации перед развёртыванием. Кластер, RLS отраслевых решений, профиль безопасности клиент-серверного кластера и нагрузка требуют отдельной приёмки.
