# Проверка версии 2.1.1 и расширения 1.2.1

20 ноября 2026 года защиту проведённых документов проверили на отдельной файловой 1С 8.3.27.1644 в Windows x64. Публикация Apache принимала подключения через loopback. SHA-256 проверенного файла OneCMCP.cfe — `4dbaadfbcf3b1e0928630881aed305292d67054c562e89bfcb14e19c2e1965d1`.

## Состояние до и после отказа

Для каждого вызова штатно проводили новый документ с суммой 10. Обработчик проведения формировал две активные записи регистра с суммами 4 и 6. Редактору дали прикладные права на запись и удаление, а администратор добавил коллекцию в область записи расширения. Для MCP включили физическое удаление. При таком наборе прав в предыдущем испытании физическое удаление проведённого документа прошло успешно.

| Попытка | Прямой POST к /hs/onec_mcp/v1/change | Применение плана через MCP |
| --- | --- | --- |
| Изменить сумму 10 на 20 | HTTP 422, `posted_document` | Отказ 1С. В журнале `rejected`, HTTP 422. |
| Установить пометку на удаление | HTTP 422, `posted_document` | Отказ 1С. В журнале `rejected`, HTTP 422. |
| Удалить физически | HTTP 422, `posted_document` | Отказ 1С. В журнале `rejected`, HTTP 422. |

Один сценарий независимо прошли исходный модуль Python, установленный wheel и готовый Windows EXE. До и после каждой попытки отдельный метод тестовой конфигурации считывал объект и записи регистра по регистратору. Совпали GUID, дата, номер, сумма, признак проведения, пометка и версия данных. Совпали обе записи регистра, включая регистратор, период, номер строки, сумму и активность. В профиле MCP поле `Posted` было скрыто. Решение об отказе принимал сервер 1С по состоянию объекта под блокировкой. [Снимки до и после из прогона готового EXE](https://github.com/zhumaniezov/onec-claude-mcp/blob/v2.1.1/docs/posted-document-results.json)

## Контрольные сценарии

- План подготовили для непроведённого документа, затем в другом сеансе провели его и попытались применить ранее выданный билет. Применение отклонено. По сравнению со снимком сразу после проведения документ и движения сохранились.
- Для черновика, документа с запретом проведения в метаданных и элемента справочника прошли создание, изменение, пометка и физическое удаление. После удаления каждый объект вернул 404.
- Автотесты проверили совместимость со старым расширением, диагностику HTTP 422 и запись отказа в аудит. При отсутствии признака `protectsPostedDocuments` коннектор останавливает отправку изменения существующего документа, в том числе при смене версии расширения между предпросмотром и применением.

Установка wheel в отдельное окружение прошла 42 автотеста. Конфигуратор загрузил и применил один и тот же CFE на 8.3.27.1644 и 8.3.18.1208 и проверил модули в серверном контексте и для внешнего соединения. Выгрузки из собранного CFE сверены с исходниками на обеих сборках. Валидатор расширения сообщил 0 ошибок и два прежних предупреждения о языке. BSL Language Server сообщил 0 ошибок и 18 предупреждений.

Полный сценарий с движениями относится к 8.3.27.1644. Промышленный кластер и прикладные конфигурации заказчика в этом испытании не использовались. [Протокол предыдущего релиза](https://github.com/zhumaniezov/onec-claude-mcp/blob/v2.1.0/docs/verification.md)
