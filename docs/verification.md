# Проверка Python-коннектора 2.0.0

20 ноября 2026 года обе поставки прошли проверку в Windows x64 на отдельных копиях двух тестовых файловых баз 1С 8.3.27.1644. Базы публиковал Apache 2.4.71 на loopback. Для теста использовались демонстрационные объекты, а для подключения Claude Code — отдельный профиль настроек.

| Проверка | Результат |
| --- | --- |
| Установленный wheel | CPython 3.12.10, MCP SDK 1.30.0, httpx 0.28.1. Запуск из отдельного каталога в режиме Python `-I`. Импорт из site-packages проверен по содержимому wheel. |
| Автономный Windows EXE | PyInstaller 6.22.3. В PATH тестового процесса отсутствовали Python и Node.js. |
| Claude Code 2.1.317 | Готовый EXE и установленный wheel по отдельности получили статус **Connected** по stdio. |
| Автоматические тесты | На Python прошли 26 тестов профилей, схемы, OData, HTTP-транспорта, предпросмотра и MCP. Четыре теста повторно прошли на готовом EXE, включая полный цикл изменения через stdio и завершение по EOF. |
| Файловые базы | Независимый stdio-клиент провёл по три цикла CRUD для EXE и для wheel. Проверены создание, фильтрация, чтение по GUID, изменение, пометка и физическое удаление. Запрашивались справочник и документ. После удаления возвращался HTTP 404. |
| Повтор и конфликт | Повторное применение билета и применение плана с устаревшей версией были отклонены. |
| Права и строки | Проверены разрешённые роли и поля, исключение скрытого реквизита из ответа CFE, ответ 403 без роли и ограничение длины на этапе подготовки. Без доступа к CFE изменение, усечённое платформой, отразилось в verification.differences. |
| Завершение | После закрытия stdin оба дистрибутива завершились с кодом 0, без лишних байтов в stdout и stderr. |

В поставке используется тот же бинарный **OneCMCP.cfe 1.1.0**. SHA-256 — `55cad480f2613a0a983d613a7808c8ece30197d5142edf3d0e2adeeaa74f1504`. Его загрузка и проверка модулей на 8.3.18.1208 и 8.3.27.1644 зафиксированы в [протоколе предыдущего релиза](https://github.com/zhumaniezov/onec-claude-mcp/blob/v1.0.0/docs/verification.md).

Проверка реального CRUD относится к файловой платформе 8.3.27.1644 под Windows. Клиент-серверный кластер, отраслевые обработчики записи и другие ОС требуют отдельной приёмки. Поддержка точных числовых литералов, структур табличных частей, чтения регистров и ограниченной потоковой распаковки gzip/deflate проверена автоматическими тестами.

При записи через OData остаётся интервал между последней проверкой версии и самой записью. В предыдущем испытании файловая публикация приняла устаревший If-Match. Предпросмотр и проверка версии со стороны коннектора не обеспечивают атомарной блокировки для других сеансов.
