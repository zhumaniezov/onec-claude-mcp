# Коннектор 1С для Claude Code

Подключите одну или несколько баз 1С к Claude Code и обращайтесь к ним по имени. Коннектор версии 2.3.0 написан на Python. Для Windows x64 доступен готовый EXE со встроенным интерпретатором. Для других систем и Python-окружений доступен wheel. Расширение 1С версии 1.3.0 входит в комплект. [Скачать релиз](https://github.com/zhumaniezov/onec-claude-mcp/releases/tag/v2.3.0)

**Переход с 2.2.0.** Загрузите в базу **OneCMCP.cfe 1.3.0**, примените расширение и откройте новый сеанс. Обновите EXE или wheel и перезапустите подключение Claude Code. В `onec_status` проверьте `extension.repostsPostedDocuments = true` и `extension.postingOperations = true`. Проведённые документы теперь можно изменять: расширение записывает их с перепроведением в той же транзакции. Интеграционному пользователю для этого нужны права **Проведение** и, для пометки удаления проведённых документов и операции `unpost`, **ОтменаПроведения**. Коннектор 2.3.0 со старым расширением 1.2.1 продолжает отклонять изменение проведённых документов.

**Переход с 2.1.1 на Windows.** Обновите EXE или wheel. В каждом профиле с авторизацией замените пару `usernameEnv` и `passwordEnv` или поле `tokenEnv` на `"credentialRef": "demo"` со своим именем записи. Сохраните данные по шагу 2. Уберите прежние переменные из настроек пользователя, скриптов запуска, профиля оболочки и настроек Claude/MCP, где вы их задавали. Закройте прежние сеансы Claude и оболочки, затем запустите Claude из нового процесса с чистым окружением. Уже запущенное приложение может сохранять старые значения. Если пароль когда-либо попал в историю или журнал, смените его в 1С и обновите запись в Windows.

При переходе с 2.1.0 также установите **OneCMCP.cfe 1.2.1**, примените расширение и откройте новый сеанс. В `onec_status` проверьте `extension.protectsPostedDocuments = true`.

При обновлении с 2.0.0 также задайте область записи по шагу 1 и назначьте интеграционному пользователю **MCP_АтомарнаяЗапись**. Проверьте правила чтения существующих профилей.

| Задача | Поддержка |
| --- | --- |
| Найти объект по русскому синониму | Расширение возвращает доступные текущему пользователю справочники и документы. |
| Узнать структуру публикации | Коннектор читает OData EDMX и показывает коллекции, ключи, реквизиты и поля табличных частей. Расширение уточняет длины строковых реквизитов объекта, доступных текущему пользователю. |
| Прочитать данные | Страницы опубликованных наборов, включая регистры. Есть выбор полей, фильтры, сортировка. Справочник или документ можно открыть по GUID. |
| Создать и изменить | Справочники и документы с одиночным ключом Ref_Key типа Edm.Guid. Можно создать записи с табличными частями. При изменении полная замена табличной части включается явно. |
| Удалить | Две отдельные операции — установить поле DeletionMark или физически удалить конкретный объект. |

Для подключения требуется доступная веб-публикация 1С с OData v3. Подходят файловые и клиент-серверные базы, если администратор может настроить публикацию, установить расширение и выдать права. В облаке эти возможности зависят от провайдера. Проведение и отмена проведения документов выполняются через расширение. Запись наборов регистров и вызов произвольных методов конфигурации лежат за пределами этой версии.

## 1. Подготовить базу

1. В Конфигураторе откройте **Конфигурация → Расширения конфигурации**, добавьте расширение и загрузите файл **extension/OneCMCP.cfe**. Примените изменение конфигурации базы и откройте новый сеанс. Точная сборка для первого стенда — 8.3.27.1644. Применимость к конкретной конфигурации проверяется при установке.
2. Дайте интеграционному пользователю роль **MCP_ДоступКМетаданным** для диагностики и чтения метаданных. Для изменения существующих записей добавьте **MCP_АтомарнаяЗапись**. Прикладные роли должны разрешать соответствующие действия с конкретными данными. Ограничения доступа на уровне записей продолжает применять 1С.
3. В публикации Apache или IIS включите **Публиковать стандартный интерфейс OData**. В самой базе настройте состав стандартного интерфейса OData. В типовых решениях для этого есть настройка автоматического REST-сервиса. Включите нужные объекты и их зависимости, сохранив ранее опубликованные.
4. Разрешите HTTP-сервис расширения. У него имя **MCP_Метаданные** и корневой URL **onec_mcp**. При точечной настройке существующего файла default.vrd добавьте элемент service в его секцию httpServices. Примените изменение публикации по процедуре своего веб-сервера.

```xml
<httpServices>
  <service name="MCP_Метаданные" rootUrl="onec_mcp" enable="true"/>
</httpServices>
```

Контрольные адреса относительно корня публикации — **/odata/standard.odata/$metadata**, **/hs/onec_mcp/v1/capabilities** и **/hs/onec_mcp/v1/metadata**. Потоки данных и права обслуживает платформа. При записи OData исполняются обработчики конфигурации с особенностями, включая отличия от интерактивных проверок заполнения. [Публикация OData](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Integration/Publishing_standard_REST_API_for_your_infobase/) · [Поведение REST-интерфейса 1С](https://1c-dn.com/1c_enterprise/rest_interface/)

**Разрешить изменение существующих объектов.** В новой базе список разрешений расширения пуст. Администратор с ролью **MCP_НастройкаЗаписи** и обычными правами на чтение состава OData задаёт точные имена опубликованных справочников и документов. Для HTTPS-публикации с Basic в PowerShell 7 замените адрес и имена объектов следующего примера.

```powershell
$publication = 'https://onec.example.org/demo'
$administrator = Get-Credential -Message 'Администратор области записи 1С'
$scope = @{ collections = @('Catalog_ПозицииСтенда') } | ConvertTo-Json -Compress
Invoke-RestMethod -Method Post -Uri "$publication/hs/onec_mcp/v1/write-scope" `
  -Authentication Basic -Credential $administrator -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($scope))
```

Команда заменяет весь список и возвращает принятые имена. Пустой массив отзывает все разрешения расширения. При исключении объектов из публикации обновите и этот список. Интеграционной учётке для изменения назначайте **MCP_АтомарнаяЗапись** и прикладные права. Настройку списка оставьте отдельной учётной записи администратора. Стандартный OData, в том числе создание новых объектов, подчиняется своим правам и настройкам публикации.

## 2. Настроить профиль

Распакуйте **onec-claude-mcp-v2.3.0-win-x64.zip** в постоянный каталог, например **C:\Tools\onec-claude-mcp**. В этом каталоге должны лежать **onec-claude-mcp.exe**, **examples** и **extension**. Готовый EXE включает Python, официальный MCP SDK, HTTP-клиент и поддержку Диспетчера учётных данных Windows.

Скопируйте **examples/profiles.example.json** как **profiles.json**. В publicationUrl укажите корень вашей публикации, например **https://onec.example.org/demo**. Для второй базы добавьте отдельный профиль в bases. Имена профилей и значения credentialRef используют латинские буквы, цифры, дефис и подчёркивание.

Пример рассчитан на тестовый справочник **Catalog_ПозицииСтенда**. Замените его имя и поля именами из опубликованной схемы своей базы. Пустой массив **readCollections** закрывает все коллекции. Если задан **readFields**, доступны только перечисленные в нём коллекции и поля. Правила действуют для списков, поиска по метаданным, описания объектов, фильтров, сортировки и предпросмотра. Для открытия по GUID укажите **Ref_Key**, для получения версии добавьте **DataVersion**. Запись также ограничена **writeCollections** и правами в самой 1С.

В **readFields** укажите **Строки/Цена**, чтобы показать только один столбец табличной части, либо **Строки**, чтобы разрешить её целиком. Полная замена существующей табличной части требует доступа ко всей части. В узком профиле подпись, паспортные данные, счета и другие ненужные поля можно полностью исключить из ответов Claude.

### Сохранение пароля или токена на Windows

Запустите следующую команду самостоятельно в обычном терминале под той же учётной записью Windows, из которой будет запущен Claude Code. Укажите **имя профиля** из `bases`. Введите логин 1С и пароль по приглашению программы. Ввод пароля скрыт. Для шлюза с Bearer-токеном укажите `--credential-type bearer` и введите токен в скрытом приглашении.

```powershell
$server = 'C:\Tools\onec-claude-mcp\onec-claude-mcp.exe'
$profiles = 'C:\Tools\onec-claude-mcp\profiles.json'
& $server --config $profiles --credential-set demo --credential-type basic
```

Программа создаёт запись в разделе **Диспетчер учётных данных → Учётные данные Windows → Общие учётные данные**. Имя записи зависит от `credentialRef` и нормализованного адреса публикации, включая путь к базе. Для другого адреса сохраните отдельную запись. Для ротации сначала измените пароль в 1С или получите новый токен у шлюза, повторите команду с `--replace` и перезапустите подключение MCP. Удалить ненужную запись можно в Диспетчере учётных данных. Пароль и токен вводятся только в терминале настройки. Поля для них в файле профилей, аргументах запуска и инструментах MCP отсутствуют.

Если публикация допускает анонимное чтение, удалите `credentialRef` из такого профиля. Для локального HTTP укажите `allowLoopbackHttp` равным true и адрес localhost, 127.0.0.1 или [::1]. Для остальных адресов требуется HTTPS. Если используется внутренний удостоверяющий центр, укажите путь к доверенному PEM-набору в `SSL_CERT_FILE`.

### Границы защиты

Коннектор читает секрет средствами Windows при открытии соединения и использует его в памяти для HTTP-аутентификации. Claude получает результаты инструментов. Секрет не требуется в окружении Claude или его дочерней оболочки. Другой процесс под той же учётной записью Windows может обратиться к тому же хранилищу. Изоляция от программ, запускаемых Claude под этой учётной записью, требует отдельной защищённой службы под другой учётной записью либо иной границы доступа ОС. [Модель доступа Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credreadw)

Действительные права на базу определяют публикация 1С, прикладные роли и ограничения доступа на уровне записей (RLS). Выдавайте интеграционному пользователю только нужные объекты и операции. Правила `readFields`, `writeCollections`, предпросмотр и журнал относятся к вызовам через MCP. При отдельном обращении к OData действуют права пользователя 1С и настройки публикации. Защиту проведённых документов и область записи проверяет серверный метод расширения `/v1/change`. Создание объектов коннектор выполняет через OData.

Файл **profiles.json** задаёт `writeCollections`, `physicalDelete` и `readFields`. Храните его вне каталога проекта и запретите Claude Code изменять его, добавив в настройки правила с вашим путём:

```json
{"permissions": {"deny": ["Edit(C:/Tools/onec-claude-mcp/**)", "Write(C:/Tools/onec-claude-mcp/**)"],
                 "ask": ["mcp__onec__onec_apply_change"]}}
```

## 3. Зарегистрировать в Claude Code

В каталоге проекта, где нужен Claude, выполните в PowerShell. Путь в первой строке должен указывать на распакованный комплект.

```powershell
$connector = 'C:\Tools\onec-claude-mcp'
$server = Join-Path $connector 'onec-claude-mcp.exe'
$profiles = Join-Path $connector 'profiles.json'
claude mcp add --transport stdio --scope local onec -- $server --config $profiles
claude mcp get onec
claude
```

**Connected** подтверждает связь Claude Code с локальным процессом. После запуска откройте **/mcp** или попросите Claude: «Проверь базу demo инструментом onec_status. Покажи отдельно результат OData и расширения». Убедитесь, что оба значения ok равны true и количество опубликованных коллекций соответствует ожиданию. [Документация Claude Code](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server)

Если имя onec уже занято прежней версией, посмотрите её область через **claude mcp get onec**. Для записи в local выполните **claude mcp remove --scope local onec** и добавьте новую команду в той же области. Для user или project подставьте соответствующую область.

### Запуск из Python

Для Python 3.11+ скачайте файл **onec_claude_mcp-2.3.0-py3-none-any.whl** из релиза. При первом подключении сохраните шаблон как **profiles.json** рядом с wheel, заполните его по шагу 2 и установите расширение по шагу 1. При обновлении укажите существующий файл профилей. [Шаблон профиля](https://raw.githubusercontent.com/zhumaniezov/onec-claude-mcp/v2.3.0/examples/profiles.example.json) · [Расширение 1С](https://github.com/zhumaniezov/onec-claude-mcp/releases/download/v2.3.0/OneCMCP.cfe)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\onec_claude_mcp-2.3.0-py3-none-any.whl
$python = (Resolve-Path .\.venv\Scripts\python.exe).Path
$profiles = (Resolve-Path .\profiles.json).Path
& $python -m onec_mcp --config $profiles --credential-set demo --credential-type basic
claude mcp add --transport stdio --scope local onec -- $python -m onec_mcp --config $profiles
```

На Linux и macOS интерпретатор находится в **.venv/bin/python**. Пропустите команду `--credential-set`. Для аутентификации на этих ОС сохранена поддержка явных ссылок на переменные процесса MCP через `usernameEnv` и `passwordEnv` или `tokenEnv`. Поле `credentialRef` требует Windows. Если экспортировать секрет в родительскую оболочку Claude, он может стать доступен его инструментам. При регистрации передайте абсолютные пути к интерпретатору и файлу профилей. Для установки wheel из публичной сети pip загружает зависимости. Архив для Windows уже содержит все библиотеки.

## 4. Первое чтение и первая запись

1. Попросите: «В demo найди по синониму нужный мне справочник, покажи его имя в публикации OData, ключ и поля». Для названия используйте термин из вашей базы.
2. Затем: «Покажи первые пять записей. Выбери только ссылку и наименование».
3. Чтобы включить запись, внесите **точное имя EntitySet из onec_collections** в массив writeCollections этого профиля. Например, если стенд показал Catalog_ПозицииСтенда, укажите **["Catalog_ПозицииСтенда"]**. Значение **["*"]** открывает все поддерживаемые справочники и документы в пределах прав пользователя. Перезапустите подключение в Claude Code после изменения файла. Пустой список оставляет базу в режиме чтения.
4. Попросите: «В demo подготовь создание тестовой позиции с наименованием “Проверка MCP”. Покажи план и дождись моего подтверждения». После применения вернётся ответ 1С. Для последующего изменения Claude читает объект по Ref_Key, получает актуальную DataVersion и показывает значения до и после.
5. Для физического удаления требуется дополнительно установить **physicalDelete** в true. Действие delete вызывает физическое удаление объекта в расширении. Для обычного процесса удаления с контролем ссылок используйте штатную процедуру базы. Действие mark устанавливает DeletionMark, а у проведённого документа одновременно отменяет проведение. Каскадная пометка подчинённых объектов не выполняется. Проведённый документ физически удалить нельзя: сначала отмените проведение. [Пометка и удаление в 1С](https://1c-dn.com/library/using_the_deletionmark_field_of_a_database_object/)

Копируйте точные значения Decimal и Int64 большой разрядности строками, включая суммы в табличных частях. Это сохраняет значащие цифры при передаче через JSON.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| onec_bases | Имена настроенных баз и возможности записи. |
| onec_status | Независимая диагностика OData и расширения. |
| onec_metadata | Поиск по имени или синониму в метаданных расширения. Право на объект и его включение в публикацию проверяются раздельно. |
| onec_collections / onec_describe | Пагинация и поиск наборов, поля, ключи и структура строк табличных частей. |
| onec_list / onec_get | Страница до 100 строк или чтение ссылочного объекта по GUID. Условия фильтра объединяются через И. |
| onec_prepare_change | Предпросмотр одного create, update, mark, delete, post или unpost. Для документов поле **posting** описывает влияние на движения. Возвращает одноразовый билет на пять минут. |
| onec_apply_change | Применение показанного плана, идентификатор операции в журнале и сверка изменённых полей. Имена полей с расхождениями возвращаются в verification.differences. |

Если у всех профилей пустой writeCollections, сервер публикует только инструменты чтения. Билет привязан к точному телу запроса. Согласие человека обеспечивает интерфейс и настройки разрешений Claude Code. Для ручного согласования оставьте запрос разрешения на **mcp__onec__onec_apply_change**. Потеряв ответ после записи, сначала перечитайте объект или найдите созданную запись по бизнес-реквизитам. Запись могла завершиться.

Существующий объект меняет метод расширения **POST /hs/onec_mcp/v1/change**. В одной транзакции он блокирует объект, сравнивает версию и выполняет изменение. Конфликт требует нового предпросмотра. При недоступности метода коннектор останавливает операцию. Создание остаётся через стандартный OData. После потери связи сверьте состояние записи перед повтором, особенно при создании.

Атомарное изменение поддерживает строки, числа, булевы значения, локальную дату до секунд, однозначные ссылки на опубликованные справочники и документы и замену табличной части. Составные типы, общие реквизиты, перечисления и передача null при изменении требуют отдельной реализации. Для полной замены табличной части интеграционной учётке нужны права просмотра и редактирования всех её прикладных колонок. Обработчики записи конкретной конфигурации выполняются на стороне 1С.

EDMX содержит описание публикации и может показывать имя объекта или реквизита, данные которого недоступны пользователю. Результат чтения ограничивают права 1С. Некоторые публикации опускают MaxLength. Расширение сообщает длину поддерживаемых строковых полей верхнего уровня. Если оно недоступно, предпросмотр сообщает об этом. В результате записи **verification.checked** и **verification.differences** показывают, удалось ли сравнить переданные значения с ответом 1С или контрольным чтением. Отличаться могут также строковые представления чисел и дат, которые нормализовала платформа.

**Проведённые документы.** Расширение под блокировкой читает состояние объекта в 1С и никогда не записывает проведённый документ без пересчёта или отмены движений. Программный вызов `Записать()` без режима, в отличие от кнопки «Записать» в форме, не перепроводит документ, поэтому расширение задаёт режим явно.

| Операция | Непроведённый документ | Проведённый документ |
| --- | --- | --- |
| `update` | Обычная запись. | Запись в режиме **Проведение** в той же транзакции. Движения регистров формируются заново. |
| `mark` | Устанавливается пометка удаления. | Пометка и запись в режиме **ОтменаПроведения**. Движения удаляются. |
| `post` | Проведение. | Перепроведение без изменения реквизитов. |
| `unpost` | Отказ `not_posted`. | Отмена проведения. |
| `delete` | Физическое удаление. | Отказ `posted_document`. |

Режим проведения выбирается как в форме документа: оперативный, если он разрешён в метаданных и документ датирован текущим днём, иначе неоперативный. При оперативном проведении платформа, как и при проведении из формы, устанавливает время документа равным текущему; предпросмотр предупреждает об этом. Если обработчик проведения или записи отказал (нехватка остатков, дата запрета изменения, незаполненные реквизиты), транзакция откатывается целиком: документ и его движения остаются прежними. Расширение возвращает до 20 текстов сообщений пользователю, которые сформировала конфигурация, и коннектор показывает их Claude. Если такие тексты могут содержать скрытые профилем данные, задайте в профиле `"writeMessages": false`. Для изменения проведённого документа нужно право **Проведение**, для пометки удаления проведённого документа и `unpost` — **ОтменаПроведения**. Защита действует для вызовов коннектора и прямых вызовов `/v1/change`, включая профили, в которых скрыто поле `Posted`. Другие каналы записи в базе, в том числе стандартный OData и обычный клиент 1С, регулируются своими правами и правилами.

## Предпросмотр и журнал

В предпросмотре сверяйте базу, коллекцию, GUID, операцию и значения **before** и **after**. При замене табличной части **tableDiff** показывает номера добавленных, удалённых и изменённых строк, а также изменённые поля. Строки сопоставляются по позиции. Перестановка строк может выглядеть как несколько замен. Применение возвращает идентификатор и версию, а контрольное чтение сравнивает разрешённые изменённые поля. Для запроса согласия на каждый вызов инструмента добавьте в настройки Claude Code следующую запись, объединив её с текущими правилами.

```json
{"permissions": {"ask": ["mcp__onec__onec_apply_change"]}}
```

Для каждого применения локальный журнал **onec-audit.sqlite3** рядом с **profiles.json** хранит **operationId**, время UTC, учётную запись ОС, логин Basic при наличии, профиль, операцию, коллекцию, GUID и результат. Для другого пути задайте **--audit-db** или **ONEC_MCP_AUDIT_DB**. Предоставьте каталогу журнала права записи для процесса коннектора и ограничьте доступ к нему средствами ОС. Одна общая учётная запись интеграции не позволяет установить, какой сотрудник подтвердил план. Пароли, билеты и значения реквизитов в журнал не записываются.

Скопируйте **operationId** из предпросмотра или результата применения. Получить запись можно даже при недоступной 1С.

```powershell
& $server --config $profiles --audit-show 'c843ed87-963e-46a7-b7eb-13f6bc49cb33'
```

**committed** означает, что 1С подтвердила запись, **conflict** — конфликт, **rejected** — отказ. При **unknown** или оставшемся после сбоя **started** проверьте фактическое состояние объекта в 1С. До сохранения начальной записи журнала коннектор не отправляет изменение. Журнал локален и требует защиты и резервного копирования средствами администратора.

## Диагностика

| Результат | Что проверить |
| --- | --- |
| Нет Connected | Абсолютные пути к EXE или Python из нужного окружения и файлу профилей, синтаксис JSON. Проверьте запуск той же команды с --version. |
| Запись учётных данных не найдена | Проверьте `credentialRef`, адрес публикации и учётную запись Windows. Выполните `--credential-set` по шагу 2. |
| HTTP 401 / 403 | Проверьте срок действия пароля или токена, способ аутентификации публикации, роль расширения и права на объект. |
| Работает OData, расширение возвращает 404 | Установку и применение CFE, rootUrl, запись HTTP-сервиса в публикации. |
| Объект есть в onec_metadata, но отсутствует в onec_collections | Состав OData этой базы и права пользователя. Коннектор кэширует EDMX на 60 секунд. |
| HTTP 412 | Объект изменился. Перечитать его и сформировать новый план. |
| HTTP 422, posting_failed | 1С не провела документ. Изменение не сохранено. Причина — в сообщениях 1С из ответа. |
| HTTP 422, posted_document | Проведённый документ нельзя удалить физически. Со старым расширением 1.2.1 так же отклоняется изменение и пометка — обновите CFE. |
| HTTP 403, posting_forbidden / unposting_forbidden | Выдайте интеграционному пользователю право **Проведение** или **ОтменаПроведения** на этот документ. |
| Другой HTTP 422 | Проверьте тип, диапазон значения и прикладные ограничения записи. Сообщения 1С, если они есть, приводятся в ответе. |
| Не открывается журнал | У процесса должны быть права на каталог SQLite, включая создание временного файла транзакции. Для установки в Program Files задайте путь к журналу через --audit-db. |
| Превышен размер ответа | Уменьшить top или задать select. Настраиваемые параметры профиля включают timeoutMs и maxResponseMiB. |

## Исходники и воспроизведение

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для сборки дистрибутивов из корня репозитория в Windows x64:

```powershell
.\.venv\Scripts\python.exe -m pip install build pyinstaller==6.22.3
.\.venv\Scripts\python.exe -m build --wheel
.\.venv\Scripts\python.exe scripts/build_windows.py
.\.venv\Scripts\python.exe scripts/package_windows.py
```

Тесты поднимают локальный HTTP-сервер со своими тестовыми записями. Исходники CFE находятся в **extension/src**, сценарий сборки — в **extension/build.ps1**. Параметр **-PlatformExe** принимает полный путь к 1cv8.exe. Сценарий создаёт отдельную временную базу и выводит путь к новому файлу CFE. Результаты проверки и сравнение GitHub-проектов находятся в **docs**.
